IDENTITY-LINK MODIFICATION

Do NOT create thousands of active ingestion_review_holds merely because an observation has a possible identity relationship.

Use these relationship states:

- deterministic_link
- candidate_link
- unlinked
- rejected

A deterministic link may be created only when the documented matching criteria produce exactly one compatible production identity.

A candidate link must preserve:
- candidate draft_players ID
- matching fields
- reason the relationship is not deterministic
- source observation
- provenance

Candidate links are NOT canonical identity merges and should NOT alter draft_players.

Do not create an active manual review hold for every candidate link.

Create ingestion_review_holds only for records that prevent safe ingestion of the underlying observation itself, such as:
- missing required observation identity/name
- internally contradictory source-event identity
- another condition that prevents the observation from being stored faithfully

The 8,300 possible identity relationships should therefore remain candidate links, not 8,300 active review holds.

The one Cape Cod row with no player name should remain an actual review hold.
